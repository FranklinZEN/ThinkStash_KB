# **JIRA Epics & Tickets: Stage 2 Development Plan (Revised Priorities v2)**

This document outlines the Epics and Tickets for the upcoming development phases of the Knowledge Card System. It is designed to be AI-friendly for coding assistance, referencing PRD v3.8 and TDD v1.2.

**Overall Phasing:**

1. **Phase A: Local MVP Enhancement (Pre-GCP)** \- Focus on optimizing the existing Stage 1 MVP, implementing hashtags, applying initial UI/UX improvements locally, and conducting initial database analysis.  
2. **Phase B: GCP Migration & Core Cloud/AI Features** \- Migrate the enhanced application to GCP and develop core cloud-native and AI features.

## PHASE A: LOCAL MVP ENHANCEMENT (PRE-GCP)

Acceptance Criteria (Functional):

\* Missing database indexes on frequently queried columns (e.g., foreign keys, columns in WHERE or ORDER BY clauses) are identified and added via Prisma migrations.

Technical Approach / Implementation Notes (for AI Vibe Coder):

\* Use a PostgreSQL client (e.g., psql, pgAdmin) to run EXPLAIN ANALYZE on raw SQL queries logged by Prisma.  
\* Review Prisma queries in service files/API routes (e.g., in src/lib/services/ or directly in src/app/api/).  
\* Look for loops making database calls; refactor to fetch related data eagerly.  
\* Example of adding an index in schema.prisma: model Card { ... @@index(\[userId, folderId\]) }. Run npx prisma migrate dev.

typescript // Example for one tag const tag \= await prisma.tag.upsert({ where: { name: tagNameWithHash }, update: {}, create: { name: tagNameWithHash }, });

typescript await prisma.card.create({ data: { title: '...', // ... other card data tags: { connectOrCreate: receivedTags.map(tagName \=\> ({ where: { name: tagName }, create: { name: tagName }, })), }, }, });

\* Update Zod schemas for card creation/update to accept an array of strings for tags.
